# Git의 저장 영역

## 1. 개념

Git은 파일의 변경 내용을 작업 디렉터리, 스테이징 영역, Git 저장소의 세 공간으로 나누어 관리한다.

> **핵심:** 파일을 수정했다고 바로 커밋되는 것이 아니라 `git add`로 선택한 변경만 커밋된다.

------------------------------------------------------------------------

## 2. 쉽게 이해하기

``` text
Working Directory
  ↓ git add
Staging Area
  ↓ git commit
Git Directory(.git)
```

> **쉽게 말하면:** 작업한 파일 중 기록할 변경을 먼저 골라 둔 다음 하나의 이력으로 확정하는 과정이다.

------------------------------------------------------------------------

## 3. 사용 방법

``` bash
git add 파일명
git commit -m "커밋 메시지"
```

- `Working Directory` → 파일을 만들고 수정하는 실제 작업 공간
- `Staging Area` → 다음 커밋에 포함할 변경을 선택하는 공간
- `Git Directory` → 커밋 이력을 보관하는 `.git` 저장소

> **핵심:** `git add`는 커밋 대상을 선택하고 `git commit`은 선택한 변경을 로컬 이력으로 저장한다.

------------------------------------------------------------------------

## 4. 예제

파일을 수정하면 VSCode의 `Changes`에 표시된다. `git add`를 실행하면 `Staged Changes`로 이동하고, 커밋하면 선택한 변경이 `.git`의 이력에 저장된다.

``` bash
git add study.py
git commit -m "Python 실습 추가"
```

### 코드 해석

- `git add study.py` → `study.py`의 변경을 다음 커밋 대상으로 선택한다.
- `git commit` → 선택된 변경을 메시지와 함께 로컬 저장소에 기록한다.

------------------------------------------------------------------------

## 🟦 핵심 정리

### 💡 주요 개념

| 개념 | 의미 |
| --- | --- |
| `Modified` | 작업 파일이 변경된 상태 |
| `Staged` | 다음 커밋 대상으로 선택된 상태 |
| `Committed` | 변경이 로컬 이력에 저장된 상태 |

### 💻 주요 코드

| 코드 | 의미 |
| --- | --- |
| `git add` | 변경을 스테이징 영역에 추가 |
| `git commit` | 스테이징한 변경을 커밋 |

### ⭐ 한 줄 정리

> **Git은 작업한 변경 중 필요한 내용을 스테이징하고 커밋하여 로컬 저장소에 기록한다.**

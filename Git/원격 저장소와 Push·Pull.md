# 원격 저장소와 push·pull

## 1. 개념

로컬 저장소는 내 컴퓨터에 있는 Git 저장소이고, 원격 저장소는 GitHub처럼 네트워크를 통해 공유하는 저장소이다. `push`와 `pull`은 두 저장소의 변경을 주고받는 작업이다.

> **핵심:** 커밋만으로는 GitHub가 바뀌지 않으며 `push`해야 원격 저장소에 반영된다.

------------------------------------------------------------------------

## 2. 쉽게 이해하기

``` text
로컬 Git ── push ──> GitHub
로컬 Git <── pull ── GitHub
```

> **쉽게 말하면:** push는 로컬 커밋을 올리는 작업이고, pull은 원격 변경을 내려받아 반영하는 작업이다.

------------------------------------------------------------------------

## 3. 사용 방법

- `origin` → 일반적으로 복제한 GitHub 원격 저장소를 가리키는 이름
- `push` → 로컬 커밋을 원격 저장소로 전송
- `pull` → 원격 변경을 로컬 저장소로 가져와 통합
- `origin/main` → 원격 저장소 `origin`의 `main` 브랜치를 로컬에서 추적하는 이름

> **핵심:** 협업 중에는 원격 변경을 확인하고 통합한 뒤 자신의 커밋을 push한다.

------------------------------------------------------------------------

## 4. 예제

``` text
GitHub 변경 확인
  ↓ pull로 로컬에 반영
로컬 작업·커밋
  ↓ push
GitHub에 커밋 반영
```

> **결과 해석:** 로컬과 원격에 서로 다른 변경이 있을 수 있으므로 두 저장소의 차이를 확인하며 동기화한다.

------------------------------------------------------------------------

## 6. 주의할 점

- `push`와 `pull`은 변경이 이동하는 방향이 반대이다.
- 로컬에서 커밋한 뒤에도 GitHub에 반영하려면 별도로 push해야 한다.

------------------------------------------------------------------------

## 🟦 핵심 정리

### 💡 주요 개념

| 개념 | 의미 |
| --- | --- |
| `로컬 저장소` | 내 컴퓨터에 있는 Git 저장소 |
| `원격 저장소` | GitHub에 있는 공유 저장소 |
| `origin` | 원격 저장소에 붙이는 일반적인 이름 |

### ⭐ 한 줄 정리

> **로컬 커밋은 push로 GitHub에 보내고 GitHub의 변경은 pull로 로컬에 반영한다.**

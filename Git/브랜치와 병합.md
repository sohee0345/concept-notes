# 브랜치와 병합

## 1. 개념

브랜치(Branch)는 기준 코드에서 작업 흐름을 분리하여 독립적으로 개발할 수 있게 하는 기능이다. 작업이 끝나면 `merge`로 한 브랜치의 변경을 다른 브랜치에 합친다.

> **핵심:** 브랜치로 작업을 분리하고 완료된 변경을 받아들일 대상 브랜치에서 merge한다.

---

## 2. 쉽게 이해하기

브랜치는 같은 출발점에서 갈라진 작업 길과 같다. 기능 개발이 끝나면 기준 흐름으로 돌아와 완성된 작업을 합친다.

```text
develop
  ↓ feature 생성
feature에서 개발
  ↓ 완료
develop으로 이동
  ↓ feature merge
develop에 반영
```

---

## 3. 사용 방법

- `main` → 서비스 배포에 사용하는 안정된 코드를 관리한다.
- `develop` → feature에서 개발한 내용을 합치고 테스트한다.
- `feature` → 기능별 개발 작업을 수행한다.
- `release` → 배포 전 QA와 배포 테스트를 진행한다.
- `hotfix` → 운영 중 발생한 오류를 빠르게 수정한다.
- `merge` → 한 브랜치의 변경을 현재 브랜치에 합친다.

---

## 4. 예제

```text
feature에서 개발 완료
  ↓
develop으로 이동
  ↓
feature를 merge
  ↓
완료된 feature 삭제
```

`develop`에 `feature`의 변경을 합치려면 먼저 `develop`을 현재 브랜치로 선택해야 한다.

---

## 5. 헷갈리는 개념 비교

|구분|기준 브랜치|작업 브랜치|
|---|---|---|
|역할|다른 작업의 출발점과 통합 대상|분리된 기능 개발 수행|
|예시|`main`, `develop`|`feature`, `hotfix`|

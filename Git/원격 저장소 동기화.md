# 원격 저장소 동기화

## 1. 개념

Git의 커밋은 먼저 로컬 저장소에 기록된다. 로컬 커밋을 GitHub 원격 저장소로 보내려면 `push`하고, 원격 변경을 로컬로 가져와 반영하려면 `pull`한다.

> **핵심:** 로컬과 원격 저장소는 분리되어 있으므로 pull과 push로 변경을 동기화한다.

---

## 2. 쉽게 이해하기

로컬 저장소는 내 컴퓨터의 작업 기록이고 원격 저장소는 GitHub의 공유 기록이다. 협업할 때는 원격 변경을 먼저 받아 통합하고 내 커밋을 원격에 올린다.

```text
원격 변경 확인
  ↓ pull
로컬 작업과 commit
  ↓ push
원격 저장소에 반영
```

---

## 3. 사용 방법

- `origin` → 일반적으로 복제한 GitHub 원격 저장소를 가리키는 이름이다.
- `pull` → 원격 변경을 로컬 저장소로 가져와 반영한다.
- `push` → 로컬 커밋을 원격 저장소로 전송한다.
- `origin/main` → 원격 저장소 `origin`의 `main` 브랜치를 로컬에서 추적하는 이름이다.

---

## 4. 예제

```text
GitHub의 변경 확인
  ↓ pull
로컬에 원격 변경 반영
  ↓ 작업 후 commit
로컬 이력 생성
  ↓ push
GitHub에 커밋 반영
```

커밋만으로는 GitHub에 변경이 반영되지 않으며 별도의 push가 필요하다.

---

## 5. 헷갈리는 개념 비교

|구분|pull|push|
|---|---|---|
|방향|원격 → 로컬|로컬 → 원격|
|역할|원격 변경을 가져와 반영|로컬 커밋을 원격으로 전송|

### 💡 주요 개념

|개념|의미|
|---|---|

|`push`|로컬 커밋을 원격으로 전송하는 작업|

### 💻 주요 코드

|코드|의미|
|---|---|

### ⭐ 한 줄 정리

> **Git 협업에서는 원격 변경을 pull로 반영하고 로컬 커밋을 push로 공유한다.**

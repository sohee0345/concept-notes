# 브랜치 보호 규칙

## 1. 개념

브랜치 보호 규칙은 중요한 브랜치에 직접 변경이 들어가거나 실수로 삭제되는 일을 줄이기 위한 GitHub 저장소 설정이다.

> **핵심:** main 브랜치는 Pull Request와 승인 절차를 거쳐 변경되도록 보호한다.

---

## 2. 쉽게 이해하기

안정된 코드가 있는 main 앞에 검토와 승인이라는 안전문을 설치하는 것과 같다.

```text
dev에서 개발·테스트 → Pull Request → 검토·승인 → main 병합
```

---

## 3. 사용 방법

- `Branch name pattern` → 보호할 브랜치 이름을 지정한다.
- `Require a pull request before merging` → 병합 전에 PR을 요구한다.
- `Require approvals` → 정해진 수의 승인을 요구한다.
- `Do not allow bypassing` → 규칙 우회를 제한한다.

---

## 4. 예제

GitHub 저장소의 `Settings → Branches → Branch protection rule`에서 `main`을 지정하고 Pull Request와 승인 요구 설정을 활성화한다.

---

## 5. 헷갈리는 개념 비교

|구분|main|dev|
|---|---|---|
|역할|안정된 최종 코드 관리|개발 변경 통합·테스트|
|변경|보호 규칙과 PR 적용|개발 작업 병합|

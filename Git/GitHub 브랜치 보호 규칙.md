# GitHub 브랜치 보호 규칙

## 1. 개념

GitHub의 브랜치 보호 규칙은 `main`처럼 중요한 브랜치에 변경을 반영하는 절차를 제한하여 실수와 검토되지 않은 병합을 줄이는 저장소 설정이다.

> **핵심:** 안정 브랜치에는 직접 변경보다 Pull Request와 검토 절차를 적용한다.

------------------------------------------------------------------------

## 2. 기본 흐름

```text
dev에서 변경 작업
  ↓
Pull Request 생성
  ↓
검토와 승인
  ↓
main에 병합
```

`main`은 안정된 결과를 관리하고 `dev`는 개발 변경을 통합하고 테스트하는 브랜치로 사용할 수 있다.

------------------------------------------------------------------------

## 3. 주요 설정

| 설정 | 의미 |
| --- | --- |
| Branch name pattern | 보호할 브랜치 이름을 지정한다. |
| Require a pull request before merging | 병합 전에 Pull Request를 거치게 한다. |
| Require approvals | 정해진 수의 승인을 요구한다. |
| Do not allow bypassing | 보호 설정의 우회를 제한한다. |

설정 경로:

```text
Repository → Settings → Branches
```

------------------------------------------------------------------------

## 4. 주의할 점

- 보호할 브랜치 이름이 패턴과 정확히 일치하는지 확인한다.
- 규칙을 만든 것만으로 개발 브랜치가 자동 생성되지는 않으므로 `dev` 브랜치는 별도로 만든다.
- 승인 인원과 적용 옵션은 실제 협업 방식에 맞게 정한다.

------------------------------------------------------------------------

## 🟦 핵심 정리

### 💡 주요 개념

| 개념 | 의미 |
| --- | --- |
| 보호 브랜치 | 변경 절차가 제한된 중요한 브랜치이다. |
| Pull Request | 변경 내용을 검토한 뒤 병합하기 위한 요청이다. |
| 승인 | 병합 전에 다른 참여자가 변경을 검토했음을 확인한다. |

### ⭐ 한 줄 정리

> **GitHub 브랜치 보호 규칙은 Pull Request와 승인 절차를 통해 main의 안정성을 지킨다.**

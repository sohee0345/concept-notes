# Branch와 Merge

## 1. 개념

브랜치(`branch`)는 기존 코드의 흐름에서 작업을 분리하여 독립적으로 진행하게 해준다. 병합(`merge`)은 한 브랜치의 변경을 다른 브랜치에 합치는 작업이다.

> **핵심:** 브랜치는 작업을 분리하고 merge는 완료된 변경을 통합한다.

------------------------------------------------------------------------

## 2. 쉽게 이해하기

``` text
develop
  ├─ feature A ─┐
  └─ feature B ─┴─ merge → develop
```

> **쉽게 말하면:** 여러 갈래에서 기능을 만든 뒤 필요한 결과를 다시 한 줄기로 합치는 방식이다.

------------------------------------------------------------------------

## 3. 사용 방법

- `main` → 서비스 배포에 사용하는 안정된 코드 관리
- `develop` → 기능을 통합하고 테스트
- `feature` → 기능별 개발 작업
- `release` → 배포 전 QA와 배포 테스트
- `hotfix` → 운영 중 발생한 오류를 빠르게 수정

> **핵심:** 병합할 때 현재 선택된 브랜치가 다른 브랜치의 변경을 받아들이는 대상이다.

------------------------------------------------------------------------

## 4. 예제

``` text
main → develop → feature
                   ↓ 개발 완료
develop ←──────── merge
```

`feature`의 변경을 `develop`에 합치려면 먼저 `develop`으로 이동한 뒤 `feature`를 merge한다.

> **결과 해석:** `develop`이 현재 브랜치이므로 `feature`의 변경을 받아들인다.

------------------------------------------------------------------------

## 6. 주의할 점

- 브랜치를 만들기 전에 어느 브랜치를 기준으로 분기할지 확인한다.
- merge할 때 현재 브랜치와 가져올 브랜치를 구분한다.
- 개발이 끝난 `feature` 브랜치는 삭제하고 `develop`과 `main`은 유지한다.

------------------------------------------------------------------------

## 🟦 핵심 정리

### 💡 주요 개념

| 개념 | 의미 |
| --- | --- |
| `branch` | 독립된 작업 흐름 |
| `merge` | 다른 브랜치의 변경을 현재 브랜치에 통합하는 작업 |
| `feature` | 기능별 개발 브랜치 |

### ⭐ 한 줄 정리

> **브랜치로 작업을 분리하고 완료된 변경을 적절한 대상 브랜치에 merge한다.**

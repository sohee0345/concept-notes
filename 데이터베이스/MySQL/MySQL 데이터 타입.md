# MySQL 데이터 타입

## 1. 개념

데이터 타입은 컬럼에 저장할 값의 종류와 표현 범위를 정한다. 알맞은 타입을 선택하면 잘못된 값의 입력을 줄이고 저장 공간과 계산 방식을 명확하게 만들 수 있다.

> **핵심:** 컬럼의 목적에 맞는 데이터 타입을 선택해야 값의 의미와 정확성을 지킬 수 있다.

------------------------------------------------------------------------

## 2. 주요 데이터 타입

| 종류 | 데이터 타입 | 용도 |
| --- | --- | --- |
| 정수 | `INT`, `TINYINT` | 식별자, 나이, 수량처럼 소수점이 없는 수 |
| 정확한 소수 | `DECIMAL(p, s)` | 금액과 점수처럼 오차 없이 저장할 수 |
| 문자열 | `VARCHAR(n)`, `TEXT` | 이름, 이메일, 메모 |
| 날짜·시간 | `DATE`, `DATETIME` | 날짜 또는 날짜와 시간 |
| 논리값 | `BOOLEAN` | 참·거짓 상태 |
| 제한된 문자열 | `ENUM(...)` | 미리 정한 선택지 중 하나 |
| 구조화된 값 | `JSON` | JSON 형식의 추가 정보 |

`DECIMAL(10, 2)`에서 10은 전체 자릿수, 2는 소수점 이하 자릿수이다. `VARCHAR(50)`에서 50은 최대 문자 수를 뜻하지만 실제 바이트 사용량은 문자 집합에 따라 달라진다.

------------------------------------------------------------------------

## 3. 사용 방법

```sql
CREATE TABLE datatype_examples (
    example_id INT AUTO_INCREMENT,
    student_name VARCHAR(50) NOT NULL,
    age TINYINT UNSIGNED,
    tuition DECIMAL(10, 2),
    is_active BOOLEAN DEFAULT TRUE,
    joined_on DATE,
    last_login_at DATETIME,
    profile JSON,
    memo TEXT,
    PRIMARY KEY (example_id)
);
```

- `UNSIGNED` → 음수 범위를 사용하지 않는다.
- `VARCHAR(n)` → 최대 길이가 정해진 문자열을 저장한다.
- `DECIMAL(p, s)` → 정밀도가 중요한 수를 정확하게 저장한다.

------------------------------------------------------------------------

## 4. 타입 선택 기준

- 식별자나 개수에는 정수형을 사용한다.
- 금액처럼 부동소수점 오차를 피해야 하는 값에는 `DECIMAL`을 사용한다.
- 최대 길이를 예상할 수 있는 짧은 문자열에는 `VARCHAR`를 사용한다.
- 계산하거나 비교할 날짜는 문자열이 아니라 `DATE`나 `DATETIME`으로 저장한다.
- 값의 후보가 매우 제한적이고 안정적일 때 `ENUM`을 고려한다.

------------------------------------------------------------------------

## 5. 주의할 점

- 실제 필요보다 지나치게 큰 타입을 선택하면 저장 공간과 인덱스 효율이 나빠질 수 있다.
- 전화번호처럼 숫자로 계산하지 않는 값은 숫자형보다 문자열형이 적합하다.
- `BOOLEAN`은 MySQL에서 내부적으로 `TINYINT(1)`의 별칭으로 처리된다.

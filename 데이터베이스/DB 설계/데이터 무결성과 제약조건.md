# 데이터 무결성과 제약조건

## 1. 개념

데이터 무결성은 데이터가 정확하고 일관된 상태를 유지하는 성질이다. 제약조건은 잘못된 값이 테이블에 저장되지 않도록 데이터베이스가 검사하는 규칙이다.

> **핵심:** 제약조건을 테이블에 정의하면 애플리케이션의 실수와 관계없이 데이터베이스가 기본 규칙을 지킬 수 있다.

------------------------------------------------------------------------

## 2. 주요 제약조건

| 제약조건 | 역할 |
| --- | --- |
| `NOT NULL` | 값의 누락을 허용하지 않는다. |
| `UNIQUE` | 같은 값을 중복해서 저장하지 못하게 한다. |
| `DEFAULT` | 값을 생략했을 때 사용할 값을 정한다. |
| `CHECK` | 값이 만족해야 할 조건을 정한다. |
| `PRIMARY KEY` | 각 행을 고유하게 식별한다. |
| `FOREIGN KEY` | 다른 테이블에 존재하는 키만 참조하게 한다. |

기본키는 `UNIQUE`와 `NOT NULL`의 성질을 함께 가지며, 한 테이블에서 행을 대표하는 식별자 역할을 한다.

------------------------------------------------------------------------

## 3. 사용 방법

```sql
CREATE TABLE courses (
    course_id INT AUTO_INCREMENT,
    title VARCHAR(100) NOT NULL,
    price DECIMAL(10, 2) NOT NULL DEFAULT 0
        CHECK (price >= 0),
    level ENUM('beginner', 'intermediate', 'advanced') NOT NULL,
    PRIMARY KEY (course_id)
);
```

- `NOT NULL DEFAULT 0` → 가격을 생략하면 0을 사용하고 `NULL`은 허용하지 않는다.
- `CHECK (price >= 0)` → 음수 가격을 거부한다.
- `PRIMARY KEY (course_id)` → 강의를 고유하게 식별한다.

------------------------------------------------------------------------

## 4. 제약조건 검증 예제

```sql
CREATE TABLE students (
    student_id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(120) NOT NULL UNIQUE
);

INSERT INTO students (name, email)
VALUES ('김민준', 'minjun@example.com');
```

같은 이메일을 다시 넣으면 `UNIQUE` 제약조건을 위반하고, 이름을 생략하면 `NOT NULL` 제약조건을 위반한다. 오류 메시지는 어떤 규칙을 어겼는지 찾는 단서가 된다.

------------------------------------------------------------------------

## 5. 주의할 점

- `DEFAULT`는 컬럼을 생략했을 때 적용되며 명시적으로 `NULL`을 넣는 것과는 다르다.
- `UNIQUE`의 `NULL` 처리 방식은 데이터베이스 제품에 따라 차이가 있을 수 있다.
- 제약조건은 실제 업무 규칙을 반영해야 하며, 무조건 많이 추가하는 것이 목적은 아니다.

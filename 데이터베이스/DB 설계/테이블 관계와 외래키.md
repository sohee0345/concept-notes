# 테이블 관계와 외래키

## 1. 개념

관계형 데이터베이스에서는 중복을 줄이고 정보를 일관되게 관리하기 위해 데이터를 여러 테이블로 나눈다. 기본키는 각 테이블의 행을 식별하고, 외래키는 다른 테이블의 기본키를 참조하여 테이블 사이의 관계를 표현한다.

> **핵심:** 외래키는 두 테이블을 연결하면서 존재하지 않는 부모 데이터를 참조하지 못하게 한다.

------------------------------------------------------------------------

## 2. 관계의 종류

### 2.1 1:N 관계

한 부모 행에 여러 자식 행이 연결되는 관계이다. 한 수강생에게 여러 수강 신청이 연결되는 경우가 대표적이다. 외래키는 N쪽인 자식 테이블에 둔다.

```text
students 1 ─── N enrollments
```

### 2.2 N:M 관계

양쪽의 한 행이 상대편 여러 행과 연결되는 관계이다. 학생과 강의의 관계처럼 N:M 관계는 연결 테이블을 만들어 두 개의 1:N 관계로 바꾼다.

```text
students 1 ─── N enrollments N ─── 1 courses
```

연결 테이블에는 두 부모 테이블의 외래키와 관계 자체의 속성인 신청일, 상태, 점수 등을 저장할 수 있다.

------------------------------------------------------------------------

## 3. 외래키 정의

```sql
CREATE TABLE enrollments (
    enrollment_id INT AUTO_INCREMENT PRIMARY KEY,
    student_id INT NOT NULL,
    course_id INT NOT NULL,
    enrolled_at DATE NOT NULL DEFAULT (CURRENT_DATE),
    UNIQUE KEY uq_student_course (student_id, course_id),
    CONSTRAINT fk_enrollment_student
        FOREIGN KEY (student_id) REFERENCES students(student_id)
        ON DELETE CASCADE,
    CONSTRAINT fk_enrollment_course
        FOREIGN KEY (course_id) REFERENCES courses(course_id)
        ON DELETE RESTRICT
);
```

- `REFERENCES` → 참조할 부모 테이블과 컬럼을 지정한다.
- 복합 `UNIQUE` → 같은 학생과 강의의 조합이 중복되지 않게 한다.
- `ON DELETE CASCADE` → 부모 삭제 시 연결된 자식도 삭제한다.
- `ON DELETE RESTRICT` → 자식이 참조 중이면 부모 삭제를 막는다.

------------------------------------------------------------------------

## 4. 데이터 처리 순서

```text
부모 테이블 생성 및 데이터 추가
  ↓
자식 테이블 생성 및 외래키 값 추가
  ↓
JOIN으로 연결된 정보 조회
```

외래키는 이미 존재하는 부모 키를 참조해야 하므로 입력할 때는 부모가 먼저이다. 삭제할 때는 참조 관계에 걸리지 않도록 자식부터 처리하거나 목적에 맞는 `ON DELETE` 정책을 사용한다.

------------------------------------------------------------------------

## 5. 주의할 점

- `CASCADE`는 편리하지만 예상보다 넓은 범위의 데이터가 함께 삭제될 수 있으므로 업무 규칙에 맞게 선택한다.
- 외래키 컬럼과 참조 대상 컬럼은 호환되는 데이터 타입을 사용해야 한다.
- N:M 관계를 한쪽 테이블의 여러 컬럼으로 억지로 표현하지 말고 연결 테이블을 사용한다.

## 🟦 핵심 정리

### 💡 주요 개념

| 개념 | 의미 |
| --- | --- |
| 1:N 관계 | 한 부모 행에 여러 자식 행이 연결된다. |
| N:M 관계 | 연결 테이블을 이용해 두 개의 1:N 관계로 표현한다. |
| 외래키 | 다른 테이블의 키를 참조해 관계와 참조 무결성을 유지한다. |

### ⭐ 한 줄 정리

> **기본키로 행을 식별하고 외래키와 연결 테이블로 테이블 사이의 관계를 안전하게 표현한다.**

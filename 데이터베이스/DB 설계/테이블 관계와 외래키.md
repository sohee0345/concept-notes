# 테이블 관계와 외래키

## 1. 개념

관계형 데이터베이스는 주제별 테이블을 기본키와 외래키로 연결한다. 외래키는 자식 테이블의 값이 부모 테이블의 기본키를 참조하도록 하여 관계의 무결성을 지킨다.

> **핵심:** 기본키는 행을 식별하고 외래키는 테이블 사이의 올바른 참조 관계를 유지한다.

---

## 2. 쉽게 이해하기

기본키가 각 데이터의 고유 번호라면 외래키는 다른 테이블의 고유 번호를 적어 둔 연결표이다.

```text
students 1 ─── N enrollments N ─── 1 courses
```

N:M 관계는 연결 테이블을 두어 두 개의 1:N 관계로 표현한다.

---

## 3. 사용 방법

```sql
FOREIGN KEY (student_id) REFERENCES students(student_id)
    ON DELETE CASCADE
```

- `PRIMARY KEY` → 각 행을 고유하게 식별한다.
- `FOREIGN KEY` → 부모 테이블의 키를 참조한다.
- `ON DELETE CASCADE` → 부모 삭제 시 연결된 자식도 삭제한다.
- `ON DELETE RESTRICT` → 자식이 참조 중이면 부모 삭제를 막는다.

---

## 4. 예제

```sql
CREATE TABLE enrollments (
    enrollment_id INT AUTO_INCREMENT PRIMARY KEY,
    student_id INT NOT NULL,
    course_id INT NOT NULL,
    UNIQUE (student_id, course_id),
    FOREIGN KEY (student_id) REFERENCES students(student_id),
    FOREIGN KEY (course_id) REFERENCES courses(course_id)
);
```

연결 테이블은 학생과 강의의 N:M 관계를 표현하고 같은 신청의 중복을 막는다.

---

## 5. 헷갈리는 개념 비교

|구분|1:N|N:M|
|---|---|---|
|의미|한 부모에 여러 자식|양쪽 모두 여러 대상과 관계|
|표현|자식에 외래키|연결 테이블 사용|

---

## 🟦 핵심 정리

### 💡 주요 개념

|개념|의미|
|---|---|
|기본키|행을 고유하게 식별하는 키|
|외래키|다른 테이블의 키를 참조하는 컬럼|
|연결 테이블|N:M 관계를 두 개의 1:N으로 바꾸는 테이블|

### 💻 주요 코드

|코드|의미|
|---|---|
|`PRIMARY KEY`|기본키 정의|
|`FOREIGN KEY ... REFERENCES`|외래키 정의|
|`ON DELETE CASCADE`|부모 삭제 시 자식 함께 삭제|

### ⭐ 한 줄 정리

> **기본키와 외래키는 테이블을 연결하고 연결 테이블은 N:M 관계를 표현한다.**

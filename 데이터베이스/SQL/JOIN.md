# JOIN

## 1. 개념

`JOIN`은 관계가 있는 여러 테이블의 행을 연결해 하나의 조회 결과로 만드는 연산이다. 연결 기준은 보통 한 테이블의 기본키와 다른 테이블의 외래키이며 `ON` 절에 조건을 작성한다.

> **핵심:** JOIN의 핵심은 어떤 테이블을 연결하는지보다 어떤 조건으로 행을 짝지을지 정확히 정하는 것이다.

------------------------------------------------------------------------

## 2. 쉽게 이해하기

주문 테이블에는 고객 번호만 있고 고객 이름은 고객 테이블에 있다. 두 테이블에서 고객 번호가 같은 행을 짝지으면 주문과 고객 이름을 함께 볼 수 있다.

```text
customers.customerNumber
          =
orders.customerNumber
          ↓
고객 정보와 주문 정보가 결합된 행
```

------------------------------------------------------------------------

## 3. 사용 방법

```sql
SELECT
    c.customerName,
    o.orderNumber
FROM customers AS c
JOIN orders AS o
    ON c.customerNumber = o.customerNumber;
```

- `AS c`, `AS o` → 긴 테이블 이름 대신 사용할 별칭이다.
- `ON` → 두 테이블의 행을 연결할 조건이다.
- 컬럼 앞의 `c.`, `o.` → 어느 테이블의 컬럼인지 구분한다.

------------------------------------------------------------------------

## 4. INNER JOIN과 LEFT JOIN

| 구분 | `INNER JOIN` | `LEFT JOIN` |
| --- | --- | --- |
| 포함 범위 | 양쪽에서 조건이 맞는 행 | 왼쪽의 모든 행과 연결되는 오른쪽 행 |
| 연결 행이 없을 때 | 결과에서 제외 | 오른쪽 컬럼을 `NULL`로 표시 |
| 사용 예 | 주문한 고객만 조회 | 주문하지 않은 고객도 조회 |

`JOIN`만 쓰면 일반적으로 `INNER JOIN`을 뜻한다.

------------------------------------------------------------------------

## 5. 주의할 점

- `ON` 조건을 빠뜨리거나 잘못 쓰면 의도하지 않은 행 조합이 대량으로 만들어질 수 있다.
- 여러 테이블에 같은 컬럼명이 있으면 반드시 테이블 이름이나 별칭을 붙인다.
- 1:N 관계를 JOIN하면 부모 행 하나가 여러 결과 행으로 반복되는 것이 정상이다.

## 🟦 핵심 정리

### 💡 주요 개념

| 개념 | 의미 |
| --- | --- |
| `JOIN` | 여러 테이블의 관련 행을 연결한다. |
| `ON` | 행의 연결 조건을 정한다. |
| 테이블 별칭 | 컬럼의 소속을 간결하고 명확하게 표현한다. |

### ⭐ 한 줄 정리

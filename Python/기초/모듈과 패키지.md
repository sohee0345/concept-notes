# 모듈과 패키지

## 1. 개념

모듈은 Python 코드를 담은 `.py` 파일이고, 패키지는 관련 모듈을 폴더 구조로 묶은 것이다. 필요한 함수나 클래스를 `import`하여 다른 파일에서 재사용한다.

> **핵심:** 코드를 역할별 모듈과 패키지로 분리하면 필요한 기능을 가져와 재사용할 수 있다.

------------------------------------------------------------------------

## 2. 쉽게 이해하기

``` text
common/
  ├─ utils.py       계산 기능
  ├─ samples.py     표본 기능
  └─ ai/
      └─ ml.py      모델 기능
```

> **쉽게 말하면:** 긴 코드를 기능별 파일과 폴더에 나누고 필요한 곳에서 꺼내 사용하는 구조이다.

------------------------------------------------------------------------

## 3. 사용 방법

``` python
from common.utils import add, sub
from common.ai.ml import get_model
```

- `common` → 패키지 경로
- `utils`, `ml` → 모듈 이름
- `add`, `sub`, `get_model` → 가져올 함수
- 점(`.`) → 하위 패키지와 모듈 경로 구분

> **핵심:** 현재 프로젝트의 폴더 구조와 import 경로가 일치해야 한다.

### 절대 import와 상대 import

``` python
# 프로젝트의 패키지 경로를 처음부터 작성
from common.show import show_msg

# 현재 패키지를 기준으로 같은 패키지의 모듈을 가져오기
from .constants import ROLE
```

- 절대 import → 프로젝트의 패키지 경로를 기준으로 작성
- 상대 import → 현재 패키지를 기준으로 `.`을 사용해 작성
- `.` → 현재 패키지

### 역할별 모듈화

``` text
chatbot/
  ├─ app.py                 화면과 전체 실행 흐름
  └─ common/
      ├─ ai.py              AI 응답 생성
      ├─ constants.py       역할 상수
      ├─ history.py         대화 이력 관리
      └─ show.py            메시지 표시와 저장
```

모듈을 단순히 파일 수를 늘리는 방식으로 나누는 것이 아니라, 각 파일이 하나의 분명한 책임을 맡도록 구성한다.

------------------------------------------------------------------------

## 4. 예제

``` python
# common/ai/ml.py
def get_model() -> str:
    return "Qwen Model"
```

``` python
# app.py
from common.ai.ml import get_model

def main():
    print(f"model name: {get_model()}")

if __name__ == "__main__":
    main()
```

실행 결과:

``` text
model name: Qwen Model
```

### 코드 해석

- `from common.ai.ml import get_model` → 하위 모듈의 함수를 가져온다.
- `main()` → 프로그램의 주요 실행 흐름을 함수로 묶는다.
- `if __name__ == "__main__"` → 현재 파일을 직접 실행했을 때만 `main()`을 호출한다.

> **결과 해석:** `app.py`가 `ml.py`의 함수를 불러와 모델 이름을 출력한다.

역할별로 분리한 가위바위보 프로그램에서는 실행 파일이 각 모듈의 기능을 가져와 연결한다.

``` python
from game.constants import 게임종류
from game.prints import print_game_result
from game.가위바위보게임 import do_game

if __name__ == "__main__":
    게임실행()
```

- `constants.py` → Enum과 게임 규칙
- `inputs.py` → 사용자 입력과 검증
- `prints.py` → 결과 출력
- `가위바위보게임.py` → 게임 진행과 결과 구성
- `main.py` → 전체 기능을 연결하고 실행

## 5. 헷갈리는 개념 비교

| 구분 | 모듈 | 패키지 | 모듈화 |
| --- | --- | --- | --- |
| 형태 | `.py` 파일 | 모듈을 묶은 폴더 구조 | 기능과 책임에 따른 전체 구조 |
| 예시 | `utils.py` | `common.ai` | UI·이력·AI 로직 분리 |
| 역할 | 함수·클래스 정의 | 관련 모듈 분류 | 수정·재사용·유지보수 개선 |

------------------------------------------------------------------------

## 6. 주의할 점

- import 경로는 실제 폴더와 파일 구조에 맞춰 작성한다.
- 직접 실행할 코드와 다른 파일에서 가져다 쓸 정의를 구분한다.
- 상대 import의 `.`은 현재 패키지를 기준으로 하므로 파일의 실행 위치와 패키지 구조를 함께 확인한다.
- 서로 강하게 연결된 기능을 무조건 잘게 나누기보다 파일마다 맡을 책임이 분명하도록 구성한다.

## 🟦 핵심 정리

### 💡 주요 개념

| 개념 | 의미 |
| --- | --- |
| `모듈` | Python 코드를 담은 파일 |
| `패키지` | 관련 모듈을 묶은 폴더 구조 |
| `import` | 다른 모듈의 이름을 가져오는 문법 |
| `절대 import` | 프로젝트 패키지 경로를 기준으로 가져오기 |
| `상대 import` | 현재 패키지를 기준으로 가져오기 |
| `모듈화` | 기능과 책임에 따라 코드를 분리하는 설계 |

### 💻 주요 코드

| 코드 | 의미 |
| --- | --- |
| `from module import name` | 모듈에서 이름 가져오기 |
| `from package.module import name` | 패키지 하위 모듈에서 이름 가져오기 |
| `from .module import name` | 현재 패키지의 모듈에서 이름 가져오기 |
| `if __name__ == "__main__"` | 파일을 직접 실행했을 때만 코드 실행 |

### ⭐ 한 줄 정리

> **모듈과 패키지는 코드를 역할별 파일과 폴더로 분리하고 import로 연결하여 재사용과 유지보수를 쉽게 한다.**

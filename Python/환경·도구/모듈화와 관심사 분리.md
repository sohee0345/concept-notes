# 모듈화와 관심사 분리

## 1. 개념

모듈화는 코드를 기능과 역할에 따라 여러 파일로 나누는 것이다. 관심사 분리는 화면, 응답 로직, 설정, 이력처럼 변경 이유가 다른 책임을 서로 분리하는 설계 방식이다.

> **핵심:** 파일을 단순히 나누는 것이 아니라 각 모듈이 하나의 분명한 책임을 맡도록 구성한다.

------------------------------------------------------------------------

## 2. 쉽게 이해하기

``` text
app.py       → 화면과 실행 흐름
ai.py        → 응답 생성
constants.py → 설정과 공통 값
history.py   → 대화 이력
show.py      → 메시지 출력
```

> **쉽게 말하면:** 한 사람이 모든 일을 맡는 대신 역할별 담당자를 정하는 것과 같다.

------------------------------------------------------------------------

## 3. 사용 방법

``` python
from common.ai import get_response
from common.history import init_history
from common.show import show_msg
```

- 화면 모듈 → 다른 모듈의 함수를 조합한다.
- 로직 모듈 → 입력을 받아 결과를 만든다.
- 설정 모듈 → 여러 파일에서 공유할 값을 관리한다.
- 이력 모듈 → 상태의 초기화와 복원을 담당한다.

> **핵심:** 필요한 기능은 import하되 화면 코드 안에 세부 로직을 모두 작성하지 않는다.

------------------------------------------------------------------------

## 4. 예제

``` python
# chat_logic.py
def get_response(user_input: str) -> str:
    return f"'{user_input}'에 대한 답변입니다."

# app.py
from chat_logic import get_response

answer = get_response("안녕하세요")
print(answer)
```

실행 결과:

``` text
'안녕하세요'에 대한 답변입니다.
```

### 코드 해석

- 응답 생성은 `chat_logic.py`가 담당한다.
- `app.py`는 필요한 함수를 가져와 호출한다.

> **결과 해석:** 화면과 응답 로직을 분리해 각 부분을 독립적으로 변경할 수 있다.

------------------------------------------------------------------------

## 6. 주의할 점

- 파일 수만 늘리고 역할이 섞여 있으면 모듈화의 이점이 줄어든다.
- import 경로는 실제 폴더와 파일 구조에 맞아야 한다.

## 🟦 핵심 정리

### 💡 주요 개념

| 개념 | 의미 |
| --- | --- |
| 모듈화 | 기능별로 코드를 파일로 분리 |
| 관심사 분리 | 변경 이유가 다른 책임을 분리 |

### 💻 주요 코드

| 코드 | 의미 |
| --- | --- |
